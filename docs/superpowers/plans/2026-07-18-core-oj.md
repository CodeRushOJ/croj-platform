# CodeRushOJ Core OJ Implementation Plan

> **Execution rule:** implement each behavior test-first, keep every repository independently green, and commit at each checkpoint. Cross-repository acceptance belongs to `croj-platform`.

**Goal:** turn the existing Vue, Spring Boot, Go judge, and Go sandbox prototypes into a deployable core online judge with secure identity, versioned problems and hidden test data, durable submission delivery, Kubernetes-native judging, six real languages, administrator workflows, images, CI, and end-to-end tests.

**Compatibility decision:** migrate the backend from end-of-life Spring Boot 2.7 to Spring Boot 3.5.16 on Java 17. Spring Boot 4.1 introduces the Spring Framework 7 / Servlet 6.1 boundary, while the current Apache RocketMQ Spring line explicitly supports Spring Boot 3. The lower-risk 3.5 bridge keeps the OJ delivery path moving and can be upgraded to Boot 4 after the messaging and persistence adapters are isolated.

**Pinned application toolchain:** Spring Boot 3.5.16, Java 17, RocketMQ Spring 2.3.6, MySQL 8.4, Flyway, MyBatis-Plus Boot 3 starter, Testcontainers, Vue 3, Vite, Vitest, Vue Test Utils, MSW, Playwright, Go 1.24, Kubernetes client-go, and immutable OCI images.

## Task 4: Make submission delivery durable and idempotent

**Repository:** `croj-backend`

**Files:**
- Create: `submission/domain/*`
- Create: `submission/application/*`
- Create: `submission/adapter/persistence/*`
- Create: `submission/adapter/messaging/*`
- Create: unit, MVC, persistence, and RocketMQ integration tests
- Retire: direct RocketMQ publish from `SubmissionServiceImpl`

1. Define and unit-test monotonic states: `PENDING`, `DISPATCHING`, `RUNNING`, terminal verdicts, and `SYSTEM_ERROR`.
2. In one MySQL transaction, validate the published problem version, create the submission/attempt, increment the submit counter, and append an outbox event.
3. Publish claimed outbox rows with bounded retry and stable event IDs. Message payloads contain IDs and immutable version metadata, never source code or hidden data.
4. Mark published rows idempotently and expose outbox lag/failed-publish metrics. A broker outage must not roll back an accepted API request or lose the event.
5. Add authorization tests proving source, compiler output, and detailed judge data are visible only to the owner and authorized staff.
6. Commit as `feat(submission): add transactional judge outbox`.

## Task 6: Replace ZooKeeper and simulated judging with Kubernetes Jobs

**Repository:** `croj-judging-server`

1. Write tests for RocketMQ event decoding, duplicate event claim, retry classification, verdict mapping, and compare-and-set completion.
2. Remove ZooKeeper discovery. Configure MySQL, RocketMQ, S3, namespace, Service DNS names, worker label, image digest, deadlines, and limits through environment variables.
3. Use the Kubernetes API to create one Job per judge attempt with stable labels and an idempotent name. Use EndpointSlice/Service DNS for long-running service discovery; Jobs are scheduled to `coderushoj.io/judge-worker=true` nodes.
4. Generate a trusted init container for immutable bundle retrieval and a credential-free runner container with `emptyDir`, read-only root, dropped capabilities, RuntimeDefault seccomp, quotas, active deadline, and TTL cleanup.
5. Watch Job/Pod state, parse a bounded result contract, and conditionally commit the terminal attempt. Duplicate delivery must return the already-known result without creating a second Job.
6. Use client-go fake tests for manifests and lifecycle edges, then RocketMQ/MySQL/Kind integration tests.
7. Add a non-root digest-pinned image, CI, SBOM, and release notes.
8. Commit as `feat: orchestrate idempotent Kubernetes judge jobs`.

## Task 7: Deliver a one-shot hardened six-language runner

**Repository:** `croj-sandbox`

1. Turn the current executor into a one-shot CLI that reads a versioned JSON manifest and writes exactly one bounded JSON result.
2. Preserve useful compiler/runner code; remove ZooKeeper from the runtime path and keep gRPC only as a temporary compatibility adapter if tests require it.
3. Compile once and execute test groups for C11, C++17, Java 17, Python 3, Go, and Node.js. Record compiler/runtime versions in results.
4. Implement exact/token/float comparison, ACM stop-first, OI group scoring, output limits, deterministic locale/timezone, and explicit verdict/error taxonomy.
5. Add Linux integration and adversarial tests for TLE, MLE, OLE, fork bombs, filesystem escape, network access, signals, oversized source, malformed manifests, and special-judge abuse.
6. Produce separate immutable runtime images where language isolation or size requires it. Images run non-root and need no Kubernetes API, database, RocketMQ, or S3 credential.
7. Commit as `feat: ship hardened one-shot judge runner`.

## Task 10: Core OJ end-to-end and capacity acceptance

**Repository:** `croj-platform`

1. From a clean three-node Kind cluster, register and authenticate a user, create a problem version, upload hidden data, publish it, and submit all six languages.
2. Assert AC, WA, CE, RE, TLE, MLE, OLE, system retry, duplicate message, and worker-node loss behavior.
3. Verify hidden data never appears in browser/API/log artifacts and unauthorized users cannot read source or detailed results.
4. Run 100 concurrent submissions capped at 20 parallel Jobs; prove no lost/duplicated terminal result and record queue/judge latency.
5. Retain JUnit, Go, Playwright, logs, manifests, screenshots, SBOMs, and failed-Pod diagnostics as CI artifacts.
6. Rehearse clean install, backup/restore, upgrade, and rollback before marking Core OJ complete.
