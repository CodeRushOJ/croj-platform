# CodeRushOJ 真实产品闭环实施计划

## 阶段 1：消除伪闭环并固定契约

- 为真实题目详情、管理鉴权、错误状态补前端失败测试。
- 移除主产品路径的预览 mock，保留的演示夹具必须隔离到测试目录。
- 固定题目版本、测试包、提交消息和回调 schema。
- 修复比赛提交越权、私有比赛题目快照与榜单版本碰撞阻断项。

验收：前端不会在 API 不可用时展示伪造题目；后端安全回归测试全绿。

## 阶段 2：题目工作台与测试包

- 先写 ZIP 安全校验、上传授权、重复上传和发布事务测试。
- 实现对象存储适配器与本地 S3 兼容配置。
- 实现管理端题目草稿、测试包上传、校验结果和发布 UI。
- 补充 OpenAPI、manifest 示例和管理员操作文档。
- 建立题目导入 Parser SPI、统一 `ProblemImportDraft` 和预检作业 API。
- 以固定上游提交的 FreeProblemSet XML/ZIP 样例先完成 FPS 1.1/1.2 解析、XXE/实体扩展防护、字段映射和批量导入测试。
- 再实现 CodeRush 原生包、ICPC problem package 与 Polygon package 适配器；格式不支持项必须作为预检警告返回。

验收：浏览器可上传测试包或 FPS 题包，预检确认后发布；匿名用户读取同一版本题面，隐藏用例摘要与原包审计信息一致。

## 阶段 3：提交到判题结果

- 完成 outbox/MQ 契约、重试和幂等测试。
- 将已实现的 Judging 固定版本测试包与 Sandbox EndpointSlice 能力接入部署。
- 实现提交、状态轮询、编译信息和分用例结果页面。
- 在 Kind 中加入最小真实 C/C++ 判题 E2E。

验收：浏览器提交 Accepted 与 Wrong Answer 样例均得到真实、可重复结果。

## 阶段 4：社区与运营闭环

- 数据库迁移增加讨论资源关联和系统公告 scope。
- 实现题目/比赛讨论、题解、系统公告完整权限与分页接口。
- 管理入口迁入用户菜单，增加题目、公告和系统状态工作台。
- 增加 XSS、越权、已删除资源和公告时间窗测试。

验收：题目页只显示关联讨论/题解；全局公告按发布窗口可见。

## 阶段 5：Claude 风格产品化

- 建立暖色中性 design tokens 与基础组件状态。
- 重构导航、题库、题目工作区、比赛、讨论、公告和管理页。
- 完成键盘操作、焦点、对比度、响应式和加载/空/错状态测试。

验收：所有核心页面使用统一 tokens，无 mock，移动端与桌面端可完成主流程。

## 阶段 6：部署、Pages、CI 与发版

- Compose 加入完整开发依赖并提供一条命令初始化演示数据。
- Helm/Kind 加入对象存储、数据库迁移 Job、Gateway 与应用 smoke。
- 发布 VitePress GitHub Pages，并校验站内链接和 base path。
- 增加跨仓库固定版本 E2E、SBOM、漏洞扫描和发布门禁。
- 关闭对应 Issues，更新真实变更日志，依赖顺序合并 `main` 并创建 Release。

验收：新机器按文档可部署；CI 从空环境复现真实 OJ 闭环。
